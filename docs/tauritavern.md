# TauriTavern 适配说明 · 0.8.2

## 实现与使用

同一份前端扩展可运行于 SillyTavern 和 TauriTavern。`batch-runtime.js` 判断宿主；PC SillyTavern 仍调用原服务端插件，TT 使用独立的 `batch-tt.js` 读写层。两者共用 `batch-engine.js`、`batch-adapters.js` 和 `batch-panel.js`，原有替换规则、字段白名单、逐处预览、勾选和筛选语义保持一致。

TT 无需服务端插件，也无需编辑 `config.yaml`。TT 标记存在但接口不足时明确停止，不会回退到 PC 端路径或地址。只通过当前页面同源的 TT 路由和公开宿主桥读取当前资料集，不访问另一套酒馆。

打开工作台 → 批量替换 → 选择作用范围 → 勾选具体资源 → 扫描匹配 → 展开逐处预览 → 执行替换 → 确认备份并执行。局部模式中，勾选角色卡并勾选聊天范围会处理该卡的全部聊天分支；世界书和身份可以单独勾选。成功或执行失败后会重新载入 TT，防止旧内存覆盖磁盘内容。

## 数据与接口

| 数据 | 读取 | 写入 | 备份 |
| --- | --- | --- | --- |
| User 身份 | `/api/settings/get` 的 Persona 投影，按头像 ID 区分；明确绑定当前头像时包含用户名和描述缓存 | `/api/settings/save`，仅提交所选身份投影及其所选缓存字段，其余设置用最新快照和设置版本令牌 | 完整身份描述 JSON、所选当前缓存、原始头像 PNG |
| 角色卡、开场白、内嵌世界书 | `/api/characters/all`、`/api/characters/get` 的原始 `json_data` | `/api/characters/merge-attributes`，保留未知数据字段 | 完整 data JSON、`/characters/<avatar>` 读取的原始角色 PNG |
| 独立世界书 | 设置中的 world_names、`/api/worldinfo/get` | `/api/worldinfo/edit` | 完整世界书 JSON |
| 聊天分支 | `list_recent_chat_summaries`、`/api/chats/get` | `/api/chats/save`，不强制覆盖 | 全部消息、头信息和 swipes |
| 群聊 | `/api/groups/all`、`/api/chats/group/get` | `/api/chats/group/save`，不强制覆盖 | 完整消息数组；尚未做群聊实机写入测试 |

TT 本阶段启用身份、聊天、角色内容、开场白、世界书范围。提示词、预设、全局正则和任意文本文件的批量替换仍保留在 PC SillyTavern，TT 暂不开放这些范围。工作台其他已有编辑工具保持原状。

### 0.8.1 修正角色卡读取

0.8.0 错把角色导出接口用于源数据校验。TT 导出时会从绑定的独立世界书重建 `character_book`，还会清理部分私有扩展字段；该投影不能代表角色 PNG 中的原始数据。遇到这类卡，曾出现写入后复读失败，并将实际写入误判为未修改的回退问题。

0.8.1 改用原始 `get.json_data` 进行扫描、并发检查、保存复读与恢复；PNG 备份从原始资源路径读取，已在实机核对与磁盘 SHA-256 一致。旧版 0.8.0 的角色 PNG 备份来自导出，不应视为原 PNG 的字节副本；旧 JSON 备份恢复仍需通过当前原始内容检查，存在冲突时不会覆盖。

角色卡内保存的世界书与绑定的独立世界书分别处理。TT 导出卡时会使用后者重新生成内嵌内容；若要修改绑定书中实际生效的内容，请同时选择对应的独立世界书，不会因选择一张卡而自动修改另一份书。

桌面端通过公开 `get_runtime_paths` 确认当前 TT 数据根目录；目录迁移未结束或路径改变即停止写入。移动端只使用当前 TT 沙盒内的扩展存储与资料集标识，不调用桌面专用路径接口。扩展存储 ABI 必须为已核对的 2，且须存在 JSON / Blob 读写能力；未知宿主类型或缺失能力会停止。

### 0.8.2 导入和移动后的归属登记

完整迁移包可能包含工作台的旧数据根目录标记。新位置与导入标记不一致时，扫描与写入仍暂停，但界面会显示当前 TT 目录、旧目录和登记按钮。核对后点击“确认将当前导入资料登记为新资料集”，先归档旧标记，再生成当前位置的新资料集 ID，并复读校验；任何目录变化、标记并发变动或归档失败都会停止登记。

登记不会修改、删除或恢复身份、角色卡、聊天、世界书等业务资料。旧事务及 Blob 全部保留，不改写旧清单的归属。旧备份显示为“迁移前／其他资料集，仅可下载”，不能直接恢复或导入为当前资料集备份，也不会因为属于其他资料集而阻塞新资料的操作。损坏、无法校验的清单仍会阻止写入。

登记会清除当前批量扫描任务和资源选择，并切换到局部模式；保留规则文本。之后必须重新选择资源并扫描，不沿用迁移前的扫描结果。移动端只登记当前沙盒，不调用桌面路径命令；手机行为有模拟检查，尚未实机验证。

## 安全和恢复

1. 扫描不改业务资料；扫描结果只保留匹配字段和原文摘要。执行前逐份重读，任何目标变化都会中止整批提交。
2. 首次运行在当前 TT 扩展存储中建立资料集 ID，备份与该 ID 及数据根目录绑定。每次业务写入再次核对归属。
3. 提交前，先保存全部待改资源的原文、预期结果、可用原始图片和事务清单，复读并校验 SHA-256；备份失败时不开始业务写入。
4. 按资源逐项记录提交状态，保存后复读比较完整语义内容。TT Persona 返回 `partial` 或未知结果均视为失败。
5. 出错立即停止，逆序检查已提交内容：仍等于预期结果时恢复；存在另外的新变化时保留当前内容，标记需要人工检查。未完成事务会阻止开始下一批替换。
6. 恢复前检查全部目标和备份。有冲突时先返回冲突列表，用户可选择保留冲突、仅恢复其他项；不会强制覆盖新内容。恢复过程中失败会保留事务日志，允许再次检查恢复。
7. TT 的本地备份位置为当前数据根目录下 `_tauritavern/extension-store/writer-workbench-batch/`。可以下载 ZIP；TT 原生文件保存流程确认交付后才算导出成功。可导入本工作台导出的、属于当前资料集的 TT ZIP，导入本身不恢复业务资料。
8. 导入限制 ZIP 路径、展开大小、条目数，校验所有内容；使用新的 Blob 键并复读，防止覆盖已有备份内容。导入不执行包内脚本。PC 备份与 TT 备份不混用。

## 实测记录与边界

在 Windows TauriTavern **2.4.0 / fff9af0333be** 的真实原生 WebView 中，已完成四类资源的实际读写：1 个身份、1 张角色卡、1 本世界书、2 个聊天分支，共 15 处匹配。另有同名身份和未勾选世界书保持不变。新增实验资源使用 `WWTT_` 前缀，未采用私人名称作为示例。

已通过：原生 Persona 部分成功响应检测、只读扫描和逐处预览、备份故障阻止写入、实际保存成功后注入响应故障的中止与回退、四类资源替换及复读、ZIP 校验与导入、新服务实例恢复、扫描后内容变化中止提交、恢复冲突保留新修改、取消扫描禁止执行。实际 ZIP 已通过 TT 原生另存为窗口保存到磁盘。故障注入发生于扩展调用层，不代表人为制造了 TT 本体故障。

另已实际验证当前身份的档案名称／描述及当前用户名／描述缓存共 4 处同步替换和恢复，原先使用的身份与缓存已复原。正式界面也完成一本实验世界书的两处替换、自动重新载入、备份恢复与再次重新载入。

限制：

- **尚未在 Android、iOS、macOS 或 Linux 实机验证。** 移动端代码复用相同公开接口并进行能力检查，不能将 Windows 结果视为全平台测试通过。
- TT 未提供跨资源原子事务或所有资源统一的条件写入令牌。逐项核对与日志恢复可处理已验证故障，不能承诺断电时整批原子性。执行期间请暂停其他编辑窗口、设备同步和生成。
- JSON / JSONL 通过 TT 原生接口保存可能规范化格式；恢复保证资源 JSON 语义，不承诺字节级排版复原。原始角色／身份 PNG 一并保留作人工恢复资料；正常恢复走原生字段接口。
- 删除了资源、修改了内容、移动到另一资料根目录或丢失资料集 ID 后，不会强行恢复；应保留 ZIP 和扩展存储，人工核查导入。
- 单资源上限 32 MiB，单批扫描／提交／导出预算 128 MiB，单批最多修改 1000 份资源。聊天列表超过 10000 份时停止，避免静默漏扫。不能安全往返的数字会显示跳过原因。
- 本地 ZIP 校验用于发现损坏，不是来源签名。只导入自己信任的备份；备份含原文及头像，公开分享扩展时不要附带个人备份。

TT 本体、安装目录与源码均未修改。PC 服务端替换引擎和业务资料未改动。运行依赖 `fflate` 的浏览器模块随扩展分发，许可见 `vendor/fflate-LICENSE`。
