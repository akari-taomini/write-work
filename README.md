# 写卡工作台 · 0.1.0

直接在 SillyTavern 里写人设、开场白、世界书和预设提示词。API 使用酒馆现有连接，无需另外填写地址和密钥。

## 安装

1. 解压安装包，找到 `sillytavern-writer-workbench` 文件夹。
2. 把整个文件夹放到酒馆安装目录的 `public/scripts/extensions/third-party/` 下。
3. 确认最终路径为 `public/scripts/extensions/third-party/sillytavern-writer-workbench/manifest.json`，不要多套一层文件夹。
4. 刷新酒馆页面。在扩展设置中点击 **✎ 写卡工作台**，或从聊天输入框旁的扩展菜单进入。
5. 先打开一张角色卡的单人聊天，再打开工作台。

这是手动安装包，不需要安装 Node 依赖、不需要编译。酒馆“安装扩展”的网址框需要 Git 仓库地址，不能填写 ZIP 文件路径。本次没有发布在线仓库。

如果酒馆由托管平台运营，需要通过平台的文件管理器安装，或让管理员放入上述目录。此扩展面向 SillyTavern，不是 TAVO 插件。

## 日常使用

- **人物设定**：左边切换人设、性格、场景、对话示例和提示词，右边直接编辑。
- **开场白**：编辑第一条和备选开场白，也可以新增备选。
- **世界书**：选择已有世界书，编辑标题、正文、关键词、停用、常驻和插入顺序；支持新增、复制、上移、下移。上移和下移改变列表显示顺序，提示词的实际插入顺序由“插入顺序”数值控制。新建整本世界书、绑定角色及更多触发条件仍在酒馆原面板操作。
- **预设**：读取当前连接类型已有的预设。聊天补全预设可编辑提示词、角色和各预设组的启用状态，也可新增提示词。自动注入的占位条目不允许直接改正文。其他类型只显示已有的文本提示字段，采样参数仍在酒馆原面板调整。
- **草稿**：编辑会自动保存在当前浏览器中。点击“写入酒馆”才会修改正式内容。人物设定和开场白属于同一份角色草稿；不同世界书、不同预设分别保存。
- **撤回与历史**：撤回本次打开后的编辑；历史保留最近 12 个快照，含写入前版本。恢复历史只修改草稿，还需要点击写入才生效。
- **创作备注**：随草稿保存，不写进角色卡或 AI 编辑请求。
- **导出／导入草稿**：用于备份和迁移。先打开同名、同类型的编辑对象再导入。草稿 JSON 是工作台格式，不是酒馆原生角色卡 JSON。
- **保存并新开试聊**：在人物设定或开场白页面使用。保存当前角色卡后，为这张卡新开一个带时间戳的聊天，不删除原聊天。这里使用的是原角色卡，不会自动创建测试角色副本；世界书和预设草稿需要先各自写入。

## AI 与预设

顶部的“写作预设”读取酒馆已有预设，选择后会同步切换酒馆的当前预设。它不是独立配置槽，不会在关闭工作台后自动切回。

选中正文的一段，打开 AI 辅助，点击润色、扩写、精简，或填写自定义要求。没有选中文字时处理当前全文。结果可以继续编辑，再替换原文或插在后面；生成结果不会直接写入角色卡。

AI 通过酒馆的后台生成接口运行，沿用当前连接、预设、角色和聊天上下文。工作台不会另存 API 密钥；每次生成会使用当前 API 的额度。若预设强调角色扮演而不愿编辑，请切换到你已有的写作预设。生成时可点击“停止生成”。

“预设”标签页是你正在修改的作品；顶部的“写作预设”是 AI 当前使用的配置。保存预设作品会让酒馆同步选中它。

## 保存与兼容性

草稿和历史保存在当前网站、当前账号命名空间下的浏览器存储中，不自动跨设备同步。清除网站数据会删除本地草稿；需要长期保存时导出备份。浏览器存储不足会明确报错，不显示保存成功。

角色卡保存只提交改动字段；世界书与预设保留未编辑的数据。保存前重新读取并比较：不同字段的修改可以合并，同一字段同时变化会停止写入。冲突时可以先导出草稿，再点击“保留历史并重新载入酒馆版本”，原草稿保留在历史中。

这是 0.1.0 初版，接口按 2026-09-16 查阅的 SillyTavern 官方 release 源码实现。旧版或修改版酒馆可能缺少所需接口。尚未在你的实际酒馆和真实 API 上联调，也没有完成真实浏览器截图验收；首次使用建议用一张测试卡确认保存与试聊行为。

已通过 12 项核心与接口自动化测试，以及一项覆盖编辑、切换、草稿恢复、保存失败、冲突恢复、AI 采用和撤回的模拟 DOM 交互测试，共 13 项。独立演示页也已验证能打开并载入演示内容。模拟测试不等同于真实酒馆端到端测试。

## 开发测试

运行时没有第三方依赖。开发测试需要 Node.js 20.19+ 和 `npm install` 安装 Happy DOM，之后执行 `npm test`。在不允许创建测试子进程的环境可使用 `node --test --test-isolation=none tests/*.test.js`（需支持该选项的 Node 版本）。
